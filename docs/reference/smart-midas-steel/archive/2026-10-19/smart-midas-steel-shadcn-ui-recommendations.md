# Smart MIDAS Steel — shadcn/ui 활용 개선 제안

> 아카이브 · 2026-10-19 정리. 과거 계획·구현·검증 기록입니다. 당시 미완료 항목이 모두 완료됐다는 뜻은 아닙니다. 현재 상태는 [현황](../../current-status.md), 남은 과제는 [로드맵](../../roadmap.md)을 우선 확인하세요.

## 1. 핵심 방향

Smart MIDAS Steel에서 shadcn/ui를 더 잘 활용한다는 것은 단순히 카드, 버튼, 색상을 shadcn 스타일로 바꾸는 것이 아니다. 핵심은 복잡한 구조설계 과정을 다음 세 가지 관점에서 명확하게 만드는 것이다.

- 단계: 사용자가 지금 무엇을 입력하고 다음에 무엇을 해야 하는지 보여준다.
- 상태: 계산 결과가 검증 완료인지, 예비 검토인지, 보강 후 만족인지 구분한다.
- 검증: 입력값, 적용범위, Gen NX 반영 결과와 설계 근거를 사용자가 확인할 수 있게 한다.

현재 제품은 이미 카드와 입력폼 중심의 shadcn 계열 인상을 갖고 있다. 앞으로는 시각적 스타일보다 단계형 위저드, 결과 상태 표현, 대용량 결과 탐색, API 작업 진행과 복구 경험에 shadcn의 상호작용 패턴을 적극적으로 적용하는 것이 효과적이다.

---

## 2. 대화형 단계 위저드

현재처럼 많은 조건을 한 화면에 한꺼번에 보여주기보다 아래 순서로 진행하는 단계형 위저드가 적합하다.

1. 프로젝트와 위치
2. 구조 형식
3. 횡단면 형상
4. 종방향 베이 복제
5. 부재와 재료
6. 하중과 내진
7. 설계 옵션
8. Gen NX 생성과 해석
9. 검토와 산출물

### 적용할 shadcn 패턴

- `Card`: 현재 단계의 질문과 핵심 입력
- `Progress`: 전체 진행률
- `Tabs`: 기본 설정과 고급 설정 분리
- `Accordion`: 상세 계수와 계산 근거
- `Alert`: 누락 입력, 적용범위 초과, 규범상 주의사항
- `Button`: 이전, 임시저장, 검증 후 다음

다음 단계로 이동할 때 화면만 전환해서는 안 된다. 현재 단계의 필수값, 값의 범위, 단위, 서로 충돌하는 조건을 검증한 후 이동해야 한다.

## 3. 횡단면 우선 모델링의 시각화

공장 철골 모델링의 핵심 흐름을 UI에서 다음처럼 명확히 분리한다.

```text
횡단면 정의 → 대표 프레임 확인 → 베이 간격 입력 → 종방향 복제
```

### 권장 UI 구성

- `Resizable Panel`: 왼쪽에는 입력, 오른쪽에는 실시간 구조 프리뷰
- `Toggle Group`: 단경간/다경간, 대칭/비대칭 선택
- `Radio Group`: 고정단/핀/사용자 지정 경계조건
- `Popover`: 부재 위치를 선택한 후 단면 지정
- `Command + Combobox`: 대만, JIS 또는 사용자 단면 검색
- `Table`: 베이별 간격과 예외 프레임 편집

베이 입력은 단순히 `6 m × 6개`만 지원하기보다 아래처럼 예외를 포함해 편집할 수 있어야 한다.

| Bay | 길이 | 프레임 형식 | 예외 조건 |
|---|---:|---|---|
| 1–2 | 6.0 m | 표준 | 없음 |
| 2–3 | 8.0 m | 표준 | 출입구 |
| 3–6 | 6.0 m | 복제 | 없음 |

이러한 구조는 사용자가 대표 횡단면을 먼저 정의하고 종방향으로 복제한다는 제품의 모델링 철학을 자연스럽게 이해하게 한다.

## 4. 설계 결과 상태의 세분화

검토 결과를 녹색 `OK`와 적색 `NG`만으로 표현하면 실제 설계 상태를 오해할 수 있다. 특히 원래 검토비는 초과하지만 스티프너 등의 보강을 적용한 후 만족하는 경우, 최종값만 표시하면 중요한 설계 과정이 가려진다.

`Badge`, `Alert`, `Tooltip`을 조합해 다음과 같이 상태를 구분한다.

| 상태 | 의미 |
|---|---|
| 검증 완료 | 규범 원문 대조와 회귀시험을 완료한 검토 |
| 보강 후 만족 | 원단면은 NG이나 보강을 적용한 최종 검토가 만족 |
| 예비 검토 | 단순화된 계산식이나 제한 조건을 적용한 결과 |
| 미검증 | 규범 원문 또는 기준 예제와 아직 대조하지 않은 결과 |
| 적용범위 밖 | 자동설계 범위를 벗어나 전문가 검토가 필요한 상태 |
| 해석 실패 | 모델, 연결 또는 API 상태를 확인해야 하는 상태 |

표시 예시는 다음과 같다.

> **보강 후 만족 · 최종 검토비 0.988**  
> 원래 기둥 플랜지 검토비는 3.021이었으며, 스티프너를 적용한 최종 연결부 검토 결과이다.

색상만으로 상태를 표현하지 말고 아이콘, 상태명, 설명을 함께 제공해야 한다.

## 5. 기본 입력과 고급 입력의 계층화

모든 구조설계 입력을 한 번에 노출하면 초보자는 압도되고, 반대로 상세 입력을 숨기면 전문가는 제어권이 부족하다고 느낀다. `Tabs`, `Accordion`, `Sheet`를 사용해 정보를 계층화한다.

### 입력 계층

- 기본 입력: 지역, 용도, 경간, 베이, 높이, 지붕 경사
- 설계 입력: 재료, 단면, 경계조건, 하중, 지진, 하중조합
- 고급 입력: 중요도계수, 노출계수, 편심, 좌굴길이, 처짐한계
- 계산 근거: 적용식, 단위, 규범 조항, 데이터 출처와 개정일

오른쪽 `Sheet`를 열면 현재 선택한 항목의 계산 근거와 규범 조항을 볼 수 있게 구성하는 것이 좋다. 사용자는 작업 흐름을 이탈하지 않고 근거를 확인할 수 있다.

## 6. Gen NX 작업 진행 경험

API 호출 목록을 기술 로그로만 표시하면 일반 사용자에게 현재 상태가 잘 전달되지 않는다. 작업 전체를 단계형 작업 큐로 보여주고, 필요할 때만 상세 API 로그를 펼쳐보게 한다.

```text
✓ 기존 모델 백업
✓ 신규 모델 생성
✓ 재료와 단면 생성
✓ 절점과 요소 생성
✓ 하중과 조합 생성
● 구조해석 실행 중
○ 결과 수집
○ 설계검토
○ 산출물 생성
```

### 적용할 shadcn 패턴

- `Progress`: 전체 작업 진행률
- `Collapsible`: 상세 API 요청과 응답 로그
- `Toast`: 저장, 완료, 재시도 등 단기 알림
- `Alert`: 실패 원인과 해결 방법
- `AlertDialog`: 현재 모델 교체, 최적화 적용 등 중요한 변경 확인

### 반드시 제공할 작업 기능

- 실행 취소
- 실패 단계부터 재시도
- 실행 전 모델로 복원
- 적용 전 변경 내역 확인
- 상세 API 로그 펼쳐보기
- 완료 후 모델 파일, 계산서, 도면 직접 다운로드

`현재 Gen NX 모델을 교체합니다`처럼 외부 모델 상태를 바꾸는 동작은 실행 전에 명확한 확인과 복구 정보를 제공해야 한다.

## 7. 결과 화면의 정보 밀도 개선

부재 수백 개의 결과는 일반 카드 목록보다 shadcn `Data Table`에 적합하다.

### 필요한 기능

- 부재군별 필터
- 검토비 내림차순 정렬
- NG 또는 경계값만 보기
- 하중조합별 결과 보기
- 변경 전/최적화 후 비교
- 표시할 열 선택
- CSV 내보내기
- 행 선택 시 Gen NX의 해당 부재 강조

상단에는 핵심 요약만 카드로 제공한다.

| 총중량 | 최대 검토비 | NG | 최적화 효과 |
|---:|---:|---:|---:|
| 42.58 t | 0.917 | 0 | 9.3% 절감 |

요약 카드에서 이상 여부를 파악하고, 아래 상세 테이블에서 원인을 탐색하는 흐름이 적합하다.

## 8. 단순형과 복잡형의 범위 경계

적용범위는 결과 화면의 면책 문구에만 표시하지 말고 입력 단계에서 판정해야 한다. `Alert`와 `Dialog`를 사용해 범위를 분명히 구분한다.

| 조건 | 권장 처리 |
|---|---|
| 단경간 일반 공장 | 자동 모델링 및 예비설계 가능 |
| 다경간 또는 중층 공장 | 제한적 자동화 또는 전문가 모드 |
| 천장크레인 포함 | 별도 크레인 하중과 피로 검토 필요 |
| 대형 개구부 또는 불규칙 베이 | 전문가 검토 필요 |
| 캐노피, 파라펫, 부분 증축 | 범위 판정 후 제한적 지원 |
| 설비 진동 또는 기계기초 | 기본 위저드 범위 밖 |
| 기초 상세설계 | 별도 기초 설계 모듈 필요 |

복잡 조건이 감지되면 다음처럼 안내한다.

> 이 프로젝트는 자동 최종설계 범위를 벗어납니다. 기본 해석 모델만 생성하거나 전문가 모드로 전환할 수 있습니다.

이러한 `scope gate`는 기능을 제한하는 장치이면서 동시에 제품의 신뢰도를 높이는 장치이다.

## 9. 접근성과 입력 품질

닫힌 설정창의 숨겨진 입력이 계속 포커스를 받을 수 있는 문제처럼, 모달과 포커스 상태는 구조설계 앱의 안전성에도 영향을 준다.

### 개선 항목

- 모달이 닫히면 원래 실행 버튼으로 포커스 반환
- 닫힌 콘텐츠와 배경 영역에 적절한 `inert` 및 접근성 속성 적용
- 오류 메시지와 해당 입력 필드 연결
- 키보드만으로 모든 단계 진행 가능
- 색상 외에 아이콘과 텍스트로 상태 전달
- 단위 표시와 숫자 입력 형식 통일
- 위험하거나 외부 상태를 변경하는 작업에 확인 절차 적용
- 입력 오류 발생 시 최초 오류 항목으로 포커스 이동
- 저장되지 않은 변경이 있으면 화면 이탈 전에 안내

Radix 기반 shadcn 컴포넌트를 사용하더라도 포커스와 숨김 상태를 임의로 변경하면 접근성이 깨질 수 있으므로 실제 키보드 및 스크린리더 테스트가 필요하다.

## 10. 추천 화면 구조

```text
┌ 프로젝트명 ─ 위치 ─ 저장 상태 ─ Gen NX 연결 상태 ┐
├ 단계 내비게이션 ───────────────────────────────┤
│ ① 프로젝트 ② 형상 ③ 부재 ④ 하중 ⑤ 설계 ⑥ 결과 │
├────────────────────┬─────────────────────────┤
│ 현재 단계 입력       │ 구조 프리뷰 / 검증 요약      │
│ 기본 설정            │ 모델 치수                    │
│ 고급 설정            │ 경고 및 적용범위             │
│ 계산 근거            │ Gen NX 반영 예정 변경사항     │
├────────────────────┴─────────────────────────┤
│ 이전             임시저장          검증 후 다음 │
└──────────────────────────────────────────────┘
```

모바일 화면에서는 구조 프리뷰와 계산 근거를 `Sheet`로 전환하고, 데스크톱에서는 좌우 분할 패널로 제공할 수 있다. 다만 실제 구조설계 업무의 주요 사용 환경을 고려하면 데스크톱 정보 밀도와 키보드 조작을 우선해야 한다.

## 11. 구현 우선순위

### P0 — 신뢰성과 오해 방지

1. 검증 완료, 예비 검토, 미검증, 보강 후 만족 상태 구분
2. 단순형과 복잡형을 판정하는 scope gate
3. Gen NX 변경 전 확인, 백업, 복원 UI
4. 모달 포커스와 숨김 콘텐츠 접근성 수정

### P1 — 핵심 작업 흐름

1. 단계형 위저드와 단계별 검증
2. 횡단면 정의와 종방향 베이 복제 화면 분리
3. Gen NX 작업 진행률, 취소, 재시도
4. 부재 결과 Data Table과 필터
5. 계산 근거와 규범 출처를 표시하는 Sheet

### P2 — 전문 제품 완성도

1. 변경 전후 모델과 최적화 결과 비교
2. 베이별 예외 프레임 편집
3. Gen NX 부재 선택 연동
4. 사용자별 입력 프리셋과 최근 프로젝트
5. 계산서, DXF, 수량표의 직접 다운로드와 버전 관리

## 12. 최종 권고

Smart MIDAS Steel에서 shadcn/ui의 장점을 가장 잘 살릴 수 있는 순서는 다음과 같다.

1. 진짜 단계형 위저드
2. 설계 결과 상태의 세분화
3. Gen NX 작업 진행, 취소, 재시도, 복구 경험
4. 부재 결과 Data Table
5. 횡단면 정의와 베이 복제의 시각적 분리
6. 기본, 고급, 계산 근거의 정보 계층화
7. 접근성과 포커스 관리

색상이나 카드 모양을 바꾸는 것만으로는 충분하지 않다. 위 항목을 적용해야 사용자가 설계 과정과 결과의 신뢰 수준을 이해할 수 있고, 제품도 단순한 입력 화면이 아니라 전문 엔지니어링 워크플로로 느껴진다.
