## 1. 평가 목적

Smart MIDAS Steel이 당초 의도한 **대만 단순 철골 공장 자동설계 위저드**로 구현되었는지를 다음 두 관점에서 통합 평가했다.

1. **웹페이지 접속 평가**
   - 대화형 단계별 위저드 UX
   - 공장 횡단면 우선 모델링과 장변 bay 복제
   - 대만 위치·설계규범 입력
   - 재료, 단면, 경계조건, 하중, 내진, 설계, 도면, 계산서, 물량 흐름
   - 단순 구조와 복잡 구조의 적용범위 구분
   - React/Vite/TypeScript 및 shadcn 계열 UX 완성도

2. **제품 라이브 검증 평가**
   - 실제 Gen NX API 연결
   - 모델 생성과 데이터 전송
   - 구조해석 실행과 결과 회수
   - LRFD 부재·사용성·접합 검토
   - 단면 자동 최적화
   - 계산서 및 DXF 출력
   - 기존 모델 보호와 백업 동작

API 키와 사용자 계정 정보는 본 보고서에 기록하지 않았다.

## 2. 종합 결론

Smart MIDAS Steel은 단순한 UI 목업이 아니라, **Gen NX와 실제로 모델과 해석결과를 주고받는 작동 가능한 기술 MVP**다. 단경간 문형골조 공장을 대상으로 모델 생성, 하중 입력, 해석, 자체 설계검토, 단면 최적화, DXF 출력까지 하나의 흐름으로 연결된다.

특히 다음 사항은 라이브 검증으로 확인되었다.

- 3차원 공장 모델이 Gen NX에 실제 생성됨
- 장변 방향 bay와 퍼린·거트·스트럿·가새가 반복 생성됨
- 15개 하중조건과 55개 하중조합이 입력됨
- Gen NX 해석이 완료되고 반력·부재력·변위가 회수됨
- 부재·사용성·접합 검토 결과가 화면에 표시됨
- 자동 최적화 후 Gen NX 모델 단면이 실제 변경됨
- 최적화 결과가 DXF 도면과 물량표에 반영됨
- 모델 재작성 전에 백업 파일이 생성됨

따라서 **자동 모델링·예비설계·견적용 제품으로는 가능성이 높다.** 다만 현재 상태에서 “대만 규정에 따른 실시설계 완료 도구”로 제공하기에는 다음 핵심 조건이 부족하다.

- 위치별 내진계수가 아직 공식 데이터로 확정 연결되지 않음
- 냉간성형강 검토가 규범 원문과 대조되지 않았다는 경고가 존재함
- 설계검토가 Gen NX의 공식 설계 모듈 결과가 아니라 웹앱 자체 계산임
- 복잡 공장에 대한 명시적 적용범위 판정과 차단 로직이 부족함
- 계산서 PDF 출력이 안정적으로 전달되지 않음
- 결과의 `OK`, 보강 필요, 전제조건이 충분히 구분되지 않음

현재 권장 제품 포지션은 다음과 같다.

> **단경간 일반 철골 공장의 자동 모델링·예비 구조검토·물량 산출 도구**  
> 실시설계 및 허가 제출 전에는 대만 현지 구조기술자의 검토와 승인 필요

## 4. 웹페이지 접속 평가

### 4.1 대화형 단계별 위저드 UX

왼쪽 가이드에서 `모델링 → 해석 → 결과 → 설계검토 → 최적화 → 계산서/도면` 순서를 안내하고, 중앙에는 명령형 대화창이 배치되어 있다. 사용자는 가이드 버튼 또는 텍스트 명령을 통해 다음 단계로 진행할 수 있다.

장점:

- 전체 업무 순서가 한 화면에 보임
- 이전 단계 결과를 다음 단계가 사용하도록 연결됨
- 명령 실행 내역과 API 로그를 확인할 수 있음
- 모델, 3D, 결과 탭이 구분되어 있음

한계:

- 모델링 시작 시 기하, 단면, 재료, 접합, 내진, 풍 입력이 긴 카드 하나에 모두 표시됨
- 사용자의 답변에 따라 질문이 하나씩 이어지는 대화형 인터뷰 방식은 아님
- 필수값, 기본값, 예시값, 공식 자동조회값의 시각적 구분이 약함
- 최적화와 설계검토처럼 오래 걸리는 작업에 진행률과 남은 단계 표시가 부족함

의도에 더 가까운 구성은 다음과 같다.

1. 프로젝트 및 적용범위 판정
2. 대표 횡단면 정의
3. 장변 bay 배열과 반복
4. 재료·단면·지점조건
5. 대만 위치·지반·중요도
6. 고정·활·풍·지진·특수하중
7. 3D 모델 검토
8. Gen NX 전송 및 해석
9. 부재·사용성·접합 검토
10. 최적화, 계산서, 도면, 물량

### 4.2 공장 횡단면과 장변방향 복제

모델링 로직은 공장 자동화 목적에 상당히 부합한다. 실제 검증 모델은 24 m 단경간 횡단면을 6 m 간격으로 6회 반복하여 전체 길이 36 m로 생성했다.

생성 결과:

- 절점 219개
- 요소 410개
- 기둥 70개 요소
- 지붕보 112개 요소
- 퍼린 84개 요소
- 거트 80개 요소
- 스트럿 18개 요소
- 박공기둥 30개 요소
- 가새 16개 요소

즉, **횡단면 기반 생성과 장변방향 반복이라는 모델링 논리는 구현되어 있다.** 다만 UI에서는 횡단면을 먼저 확정하고 bay를 복제한다는 개념이 명시적으로 드러나지 않는다. 횡단면 전용 2D 편집 화면과 장변 bay 편집 화면을 분리하면 사용자의 구조적 이해와 오류 검토가 쉬워진다.

### 4.3 대만 프로젝트·위치·설계규범 입력

확인된 입력 항목은 다음과 같다.

- 현·시와 향진시구
- 지반 분류
- SDS, SD1, S_MS, S_M1
- 구조시스템별 R
- 용도계수
- 기본설계풍속 V10
- 지형 구분
- 밀폐 또는 부분밀폐 형식
- 대만 LRFD 설계규범

행정구역 선택과 내진·내풍 입력을 한 흐름에 배치한 점은 적절하다. 그러나 화면에 SDS·SD1이 예시값이므로 실제 공사 위치 값으로 변경하라는 경고가 표시된다. 즉, 위치 선택이 곧 공식 내진계수 결정으로 이어지는 상태는 아니다.

제품화 시에는 다음이 필요하다.

- 공식 출처와 개정연도를 가진 위치별 계수 데이터베이스
- 행정구역 선택 시 계수 자동입력 및 출처 표시
- 사용자가 수정하면 `공식값`과 `사용자 재정의값`을 함께 기록
- 근단층, 지반분류, 중요도 및 구조시스템 선택의 적용조건 검증
- LRFD와 ASD의 지원 범위 또는 미지원 사실 명시

### 4.4 입력부터 산출물까지의 흐름

재료, 단면, 기하, 지점조건, 고정하중, 활하중, 풍하중, 지진하중, 부재검토, 사용성, 접합부, 최적화, 계산서, DXF와 물량까지 메뉴 구조는 잘 연결되어 있다.

하지만 다음 항목은 부족하거나 범위가 불명확하다.

- 크레인 하중과 충격계수
- 메자닌과 설비 집중하중
- 큰 출입구와 벽체 개구부
- 캐노피, 파라펫, 지붕 돌출부
- 불균등 bay와 단차
- 기계 진동 및 기계기초
- 독립기초·줄기초·말뚝기초 설계
- 접합재, 볼트, 용접, 베이스플레이트를 포함한 총수량
- 제작도 수준의 부재번호와 상세도

### 4.5 UI 기술 및 디자인 품질

React/Vite 기반 단일 페이지 애플리케이션으로서 응답성과 화면 전환은 양호했다. shadcn 계열 제품에서 기대되는 카드, 탭, 버튼, 입력 요소와 유사한 시각언어를 사용하지만, 실제 경험은 범용 shadcn 위저드보다는 맞춤형 엔지니어링 대시보드에 가깝다.

라이브 사용 중 확인된 접근성 문제:

- 닫혀 있는 API 설정창의 입력 요소가 접근성 트리에 남아 있었음
- 키보드 또는 보조기술이 숨은 자동저장 경로 입력란을 선택할 수 있었음
- 접힌 가이드 메뉴의 버튼이 접근성 트리에는 노출되는 경우가 있었음
- 장시간 작업 상태가 대화 메시지 한 줄에 의존함

닫힌 모달은 `inert` 또는 `aria-hidden`으로 완전히 제외하고, 포커스 트랩과 복귀 위치를 명확히 해야 한다.

## 5. Gen NX 제품 라이브 검증

### 5.1 시험 모델

| 항목 | 값 |
|---|---|
| 형식 | 단경간 문형골조 공장 |
| 횡단 경간 | 24 m |
| 장변 | 6 bay × 6 m = 36 m |
| 처마높이 | 8 m |
| 지붕경사 | 0.1, 약 5.7° |
| 주재료 | SN400B |
| 기둥·지붕보 초기 단면 | RH 600×200×11×17 |
| 퍼린 | CC 200×75×20/4.0 |
| 거트 | CC 200×75×20/3.2 |
| 기둥 지점 | 고정 |

### 5.2 모델 생성과 API 전송

Gen NX에 다음 데이터가 실제 작성되었다.

- 단위계
- 재료와 단면
- 절점과 요소
- 단부 릴리즈와 경계조건
- 정적 하중조건
- 자중·보하중·절점하중
- 하중조합
- 설계 관련 데이터

모델 작성 전 기존 Gen 파일을 자동 백업한 뒤 새 모델을 만들었고, 최적화 과정에서도 단면 변경 전에 다시 백업했다. 이는 초기 평가에서 우려했던 모델 손실 위험을 상당히 개선한 부분이다.

다만 실제 제품에서는 다음 단계까지 필요하다.

- 전송 전 변경사항 미리보기
- 신규 작성과 기존 모델 갱신 모드 분리
- 일부 API 실패 시 자동 롤백
- 작성 완료 후 절점·요소·하중 개수 대조
- 작업 ID와 모델 해시 기록
- 동일 요청 중복 실행 방지

### 5.3 구조해석과 결과 회수

Gen NX 해석은 정상 완료되었다. 앱은 반력, 보 요소력, 트러스 요소력과 변위를 회수했다.

초기 결과 일부:

| 항목 | 결과 |
|---|---:|
| 고정하중 수직반력 합계 | 681.695 kN |
| 앱 표시 지진중량 | 680.1 kN |
| 지붕 활하중 수직반력 합계 | 847.295 kN |
| X방향 지진 밑면전단 | 150.603 kN |
| Y방향 지진 밑면전단 | 186.622 kN |
| 기본 높이 풍속압 q(h) | 0.417 kN/m² |

고정하중 반력 합계와 앱의 지진중량은 약 0.2% 범위에서 일치하여 기본적인 하중 전달은 합리적으로 보였다. 일부 풍하중 조건에서 큰 음의 수직반력이 발생하므로 기초와 앵커 설계에서는 uplift 조합과 부호 처리를 명확히 표시해야 한다.

초기 검토 결과는 전체 410개 부재, 최대 부재 강도비 0.912, NG 0으로 표시되었다.

### 5.6 계산서, 도면과 물량

#### 계산서

계산서 버튼을 누르면 앱은 새 탭에서 계산서를 열었으며 브라우저 인쇄로 PDF를 저장하라고 안내했다. 그러나 시험 브라우저에서는 새 탭이 확인되지 않았고 PDF 파일도 직접 생성되지 않았다.

가능한 원인은 팝업 차단 또는 브라우저별 `window.open` 처리 차이다. 원인과 무관하게 제품 관점에서는 다음 방식이 더 안정적이다.

- 서버 또는 브라우저에서 직접 PDF 생성
- `계산서 PDF 다운로드` 버튼 제공
- 생성 완료 후 파일명, 페이지 수, 생성시각 표시
- 인쇄 스타일과 페이지 나눔 자동검증
- 모델 버전과 계산서 버전 연결

#### DXF

DXF 다운로드는 정상 동작했다. 생성 파일은 AutoCAD R12 `AC1009` 형식의 ASCII DXF이며 다음 내용을 포함했다.

- 5개 시트 제목
- 11개 도면 레이어
- LINE 엔티티 459개
- TEXT 엔티티 213개
- CIRCLE 엔티티 41개
- 최적화된 주골조·스트럿·가새 단면
- 최종 총량 42.58 t

이는 개념·예비설계 도면으로는 유용하다. 다만 허가도 또는 제작도로 사용하려면 부재번호, 치수체계, 접합 상세, 볼트·용접기호, 도면번호, 개정이력과 현지 도면표준을 추가해야 한다.

#### 물량

현재 물량은 주로 구조부재 중량 중심이다. 사업성과 견적 활용도를 높이려면 다음을 포함해야 한다.

- 부재별 길이·개수·단위중량
- 플레이트와 보강판
- 앵커볼트와 고장력볼트
- 용접 길이와 종류
- 도장 또는 내화피복 면적
- 로스율과 발주중량
- 공종별 합계와 CSV/XLSX 출력

## 8. 누락되거나 오해를 유발할 수 있는 요소

1. `전체 OK`가 미검증 계산 또는 보강 후 결과라는 사실을 충분히 전달하지 않음
2. 위치를 선택했지만 SDS·SD1은 예시값일 수 있음
3. LRFD만 선택 가능하지만 대만 강구조 규범의 ASD 지원 관계를 설명하지 않음
4. Gen NX 해석과 앱 자체 설계검토의 책임 경계가 화면에서 명확하지 않음
5. 철골량을 전체 공사 물량으로 오해할 수 있음
6. DXF를 허가도·제작도로 오해할 수 있음
7. 계산서가 생성되었다는 메시지와 실제 파일 전달 상태가 불일치할 수 있음
8. 단경간 적용범위를 벗어나는 입력을 사전에 차단하지 않음
9. 번체중문 화면 일부에 한국어 표현이 혼재함
10. 숨은 설정 모달의 입력란이 키보드·접근성 탐색 대상으로 남아 있음

## 10. 최종 판단

Smart MIDAS Steel은 **기술 데모를 넘어 실제 구조모델과 결과를 생산하는 MVP**다. 특히 Gen NX 모델 생성, 실제 해석, 결과 회수, 반복 단면 최적화와 DXF 반영까지 성공한 점은 제품의 핵심 가치가 이미 구현되었음을 보여준다.

다음 제품 단계의 핵심은 기능 추가보다 **신뢰성의 명문화**다. 어떤 계산을 Gen NX가 수행했고 어떤 계산을 웹앱이 수행했는지, 어떤 규정 항목이 검증되었고 어떤 항목이 아직 예비인지, 어떤 건물까지 자동화 대상인지가 명확해야 한다.

이 조건을 충족하면 단순 철골 공장 프로젝트에서 다음과 같은 실질적 가치를 제공할 수 있다.

- 초기 구조계획 시간 단축
- Gen NX 반복 모델링 자동화
- 대안 단면 비교와 물량 절감
- 예비 견적과 기술제안 신속화
- 구조기술자의 반복 작업 감소

현 시점의 권장 판정은 다음과 같다.

> **내부 시범 및 예비설계: 사용 가능**  
> **고객 대상 자동설계 서비스: 조건부 가능**  
> **검토 없이 실시설계·허가·제작에 직접 사용: 아직 부적합**

### 11.4 남은 핵심 과제

#### 1. 외부 Gen 모델 변경과 앱 상태의 불일치 감지 — 우선순위 높음

전송 직후에는 데이터를 확인하지만, 사용자가 Gen에서 단면·하중 등을 직접 수정한 뒤 해석하는 상황에 대한 동일성 확인이 부족하다. 같은 요소 ID를 유지한 채 단면을 바꾸면 회수한 해석결과와 앱에 남은 단면 정보가 달라질 수 있다. 결과의 개수·ID·유한 수치 검증만으로는 이 문제를 해결하지 못한다.

- 근거: `src/actions/build.ts`, `src/actions/analysis.ts`, `src/actions/results.ts`, `src/domain/resultValidation.ts`
- 권고: 해석·설계검토 직전 주요 모델 데이터의 스냅샷 또는 해시를 비교하고, 불일치 시 재동기화·재생성을 요구한다.
- 완료 기준: Gen에서 동일 ID의 단면·재료·절점·하중을 변경한 시험에서 이전 앱 정보로 검토를 진행하지 않는다.

#### 2. 자유골조 입력 검증을 기본 모델링과 통일 — 우선순위 높음

기본 모델링은 잘못된 입력을 차단하지만, 자유골조는 `invalid = free ? [] : ...`로 검증 대상에서 제외된다. `toSpec()`은 잘못된 숫자·베이 목록을 기존 값으로 유지하거나 정수 필드를 반올림하므로 화면 입력과 실제 생성값이 달라질 여지가 있다.

- 근거: `src/components/PlanCard.tsx`의 `invalidField()`, `toSpec()`, `invalid` 분기
- 권고: 직접 편집 방식은 유지하고 필수값·숫자·정수·베이 목록·선택값·단면 검증과 실행 차단을 공통 적용한다.
- 완료 기준: 두 모드에서 빈 값·음수·비정상 숫자·소수 개수·잘못된 베이 목록·단면 오류를 표시하며, 기존 값으로 조용히 대체해 전송하지 않는다.

#### 3. 최적화의 최선안 선택에 접합 검토 포함 — 우선순위 높음

현재 반복안 선택은 부재·사용성 NG와 중량을 중심으로 하고, 접합부는 최종안에서 계산한다. `opt.ok`에서 접합부 통과 조건을 중국에만 적용하는 차이도 있다. 현재 코드 구조에서는 접합까지 고려한 다른 유효 대안을 놓칠 수 있다. 이는 코드 검토로 확인한 판정 구조의 문제이며, 이번 평가에서 실제 접합 NG 사례를 새로 재현한 것은 아니다.

- 근거: `src/actions/optimize.ts`의 `ok`·`best` 선택, 최종 `runConnections()`, `S.opt.ok`
- 권고: 반복안마다 접합 검토를 기록하고 중국·대만에 같은 최종 통과 조건을 적용한다. 이후 접합 판재를 포함한 총중량 비교로 확대한다.
- 완료 기준: 부재·사용성은 통과하지만 접합은 NG인 후보를 최종 통과안으로 선택하지 않는다. 유효 후보가 없으면 그 사실을 명확히 표시한다.

#### 4. 프로젝트 저장·복원 및 개정 관리

입력·생성 모델·해석·검토 결과는 주로 메모리에 있다. 새로고침 또는 브라우저 종료 후 동일 프로젝트를 이어서 작업하기 어렵다. API 키를 메모리에만 두는 정책은 유지하면서 프로젝트 데이터는 별도로 보존할 필요가 있다.

- 근거: `src/state/store.ts`의 `built`, `results`, `design`, `connections`, `lastSpec`
- 권고: API 키를 제외한 프로젝트 파일 저장·불러오기부터 구현한다. 입력·결과·계산서에 프로젝트 ID·개정번호·설계기준·앱 버전을 연결한다.
- 완료 기준: 저장 파일을 다시 열어 입력을 복원하고, 복원된 결과가 현재 Gen 모델과 동기화됐는지 구분한다. 개정이 달라진 결과를 최신 결과로 표시하지 않는다.

#### 5. 국가별 계산 검증의 깊이 보강

대만은 실제 해석결과를 고정한 기준 모델 회귀가 있다. 중국은 규범 표·하중·형상 등 앵커 검증이 있지만, 대만과 동등한 전체 결과 고정 회귀를 보강해야 한다. 냉간성형강 근사, 접합 강성·회전능력, 앵커 정착 등은 여전히 상세 검토 대상이다.

- 근거: `scripts/verify-tw.ts`, `scripts/tw-golden.ts`, `scripts/verify-cn.ts`, `docs/reference/china_code_implementation.md`
- 권고: 중국 전체 결과 고정 회귀, 형상·하중·단면 경계값 사례, 독립 수계산 및 외부 기준 결과 비교를 추가한다. 검증을 빌드와 별도 자동 품질 게이트로 묶는다.
- 완료 기준: 국가별 동일 수준의 재현 가능한 기준 모델과 기대 결과를 보관하고, 계산식 변경 시 차이와 근거를 검토할 수 있다.
- 주의: 상태 표시가 명확해진 것과 계산 검증이 완료된 것은 별개다.

#### 6. 모델링 이후까지 이어지는 업무 안내

모델링 입력은 단계형으로 개선됐지만, 생성 이후에는 사용자가 가이드에서 해석·검토·최적화·출력을 찾아 실행한다.

- 권고: 생성 완료 시 다음 작업을 제시하고, 전체 업무 진행 상태와 결과의 최신 여부를 표시한다. 실패 시 재개 위치도 함께 안내한다.
- 완료 기준: 초보자가 명령어를 알지 못해도 모델 생성부터 검토·출력까지 진행하고, 선행 단계 변경으로 무효화된 결과를 식별할 수 있다.

## 12. v1.6.0 국가별 재검토 후 보완 (2026-10-17)

v1.5.0의 한국·중국·대만 전체 프로세스 재검토 후, 사용자가 선택한 **1·2·4·5번**을 구현했다. 이 단계에서 유보한 3번 대만 Q·냉간성형 원문 대조는 이후 제공된 원문을 받아 13장에서 반영했다.

### 12.1 반영 사항

| 번호 | 반영 | 범위와 잔여 조건 |
|---|---|---|
| 1 | 경간별 처짐·내부 기둥 변위 회수 | TW L/360, KR 프로젝트 기준 L/240, CN D+LR/SN/SV/SH L/180. 각 검토점에서 양쪽 지지점 변위를 부호를 유지해 보간한다. |
| 2 | 검토법 적용 한계와 등급·최적화·출력 연결 | KR B2>1.5 및 냉간성형 표 1.6-1 범위 초과는 실패 등급, 유효 최적화안 제외, 네 산출물 실행 차단. 숫자 NG와 별도로 위반 개수를 보관한다. |
| 4 | 중국 접합 계산 및 한국 독립 대조 확대 | CN 표준 구멍·간격·순유효단면·블록 전단·짧은 거셋 안정·슬롯 강관 순단면·유효 용접길이. KR Gen 결과는 같은 요소 ID의 강도 포락으로 비교하고 세장비 권고·미검토 냉간성형·누락을 구분한다. |
| 5 | 횡지지 가정의 명시·해제와 제외 물량 추적 | 플라이브레이스·새그로드·TW/KR 교차 가새에 가정/확인/없음 입력. 없음은 전체 길이, 가정은 전문가 등급. 계산서·도면·물량에도 현재 조건과 제외 항목을 표시한다. |

한국 비대칭 경간 라이브에서 중력으로 유발된 횡변위가 B2에 섞이는 문제를 추가로 확인했다. 최종 구현은 수평 EX/EY 케이스의 H와 기둥 상단 최대 변위로 층강성을 산정하고 각 조합의 P_story를 유지한다(KDS 14 31 15 4.5-6/7). 실제 2차해석/좌굴 고유치 해석을 구현했다는 뜻은 아니다.

중국 거셋 유효폭은 GB 50017 그림 12.2.2(c)의 22도 확산과 판 폭 중 작은 값을 쓰며, 순단면에서 d+4를 공제한다. c=75mm·가새 45도·볼트 2열은 상세 가정이다. 자유단·편심·실제 배치·골조 연결부, 기초·앵커 정착과 접합 회전성능은 전문가 확인 대상으로 남는다.

횡지지의 ‘확인’은 설계자가 실제 양 플랜지 지지·강성·접합·정착을 확인했다는 입력이다. 앱이 해당 상세를 자동 검증하거나 부품 물량을 모두 산정한 것은 아니다. 플라이브레이스·새그로드·클립·교차 연결재 등은 발주 물량에서 제외된다.

### 12.3 판단

세 기준의 업무 흐름과 오류 차단은 공통화됐지만 규범 검증 수준까지 같다고 보지는 않는다. 한국은 Gen 요소별 대조를 통한 추적을 강화했고, 중국은 접합 상세 계산을 확장했다. 대만 원문 반영 후에도 실제 지지/접합 상세와 아래 냉간성형 잔여 항목의 검증이 남아 있다. 수치 NG 0, 최적화 유효안, 전문가 확인 완료는 서로 다른 상태로 해석해야 한다.

### 13.1 후속 성능 과제

KR 703부재·140조합 라이브에서는 재해석 자체가 약 7~11초인데, 조합별 BEAMFORCE 표 회수가 약 185~205초 걸렸다. 최적화 전체 시간은 이 회수 단계의 반복이 지배한다. 클릭형 업무 속도 개선을 위해 결과 요청량·Gen 표 생성 비용을 따로 계측할 필요가 있다. 선형 기본 케이스의 로컬 조합 등은 후속 검토 후보이며, 기존 Gen 조합 결과와 동일성 검증 없이 이번 구현에 도입하지 않았다.
