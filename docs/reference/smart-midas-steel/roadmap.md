# 개선 로드맵

기준 버전: **v2.4.1** · 마지막 검토: 2026-10-19 · 상태: 제안, 미착수

현재 구현은 [현황](current-status.md), 과거 계획·시험은 [아카이브](archive/2026-10-19/README.md)를 참고한다. 아래는 코드·기존 시험 기록에서 확인한 잔여 항목을 정리한 작업안이다. 일정이나 구현 승인을 확정한 문서는 아니다.

## R01. 프로젝트 저장·복원·개정

- **근거:** [store](../src/state/store.ts)의 모델·입력·결과는 주로 메모리에 있다. 현재 Gen 백업/복원, 같은 탭의 입력 유지와 구분해야 한다.
- **범위:** 첫 단계는 API 키를 제외한 입력 프로젝트 파일의 내보내기/불러오기. `schemaVersion`, 프로젝트 ID·이름·개정, 코드·단위·앱 버전·단면 출처를 포함한다. 이어서 결과 보존 방식을 결정한다.
- **완료 기준:** 기본/자유골조·불균등 베이·추가 구조를 저장 후 새 탭에서 동일하게 복원한다. 손상·지원하지 않는 버전·코드/단면 오류를 조용히 치환하지 않는다. 키가 파일에 포함되지 않는다.
- **결과 상태:** 가져온 과거 결과는 현재 Gen과 동일성 확인 전까지 참조 상태다. 입력을 복원했다고 해석·검토 완료로 표시하지 않는다. 모델 변경과 연결된 기존 최신성 검증도 유지한다.
- **검증:** 입력 왕복, 구버전 마이그레이션/거부, 잘못된 파일, 키 배제, 결과 개정 불일치, 내보낸 파일로 실제 브라우저 재개.

## R02. 기본 단면·템플릿 적용 범위

- **근거:** [크레인 6건 라이브](reference/crane-travel-range.md)의 36×80m·8m 베이는 각 국가 기본 단면에서 다수 NG다. CN 기둥 GB 6.1.4의 B=99도 기록됐다. 형상 템플릿 선택을 설계 적합 판정으로 해석할 수 없다.
- **범위:** 국가 × 박공/편경사/다경간 × 대표 템플릿 × 크레인 유무의 입력·검증 표를 만든다. 기본 단면의 검증 조건과 미검증 조건을 표시하고, 확인된 후보가 있을 때만 초기 제안값에 반영한다.
- **완료 기준:** 지원 범위·초기 제안·검증된 샘플을 구분한다. 단면 부적합으로 건물 베이 수를 줄이거나 이전 모델링 단계로 돌아가도록 강요하지 않는다. 현재 NG 진단·보완 기능에서 원인과 다음 행동을 제시한다.
- **판정:** 수치 NG 외 적용 한계·B2/안정 한계·사용성·접합까지 확인한다. 단면을 크게 골랐다는 이유만으로 통과하지 않는다. 유효 후보가 없으면 그 사실과 필요한 전문 검토를 표시한다.
- **검증:** 기준 모델과 큰 모델을 분리해 재해석하고, 보완 전후 부재·사용성·접합 및 중량을 함께 남긴다. 자동 최적화의 기존 규칙을 그대로 중복 구현하지 않는다.

## R03. 라이브 시험 프로세스 장애 복구

- **근거:** KR 일부 구간의 Node `undici Parser.finish` assertion은 프로세스 종료로 이어졌다. 기존 `finally`만으로 복원되지 않아 [복구 스크립트](../scripts/restore-live-snapshot.ts)를 별도 실행했다.
- **범위:** 시험 프로세스와 독립된 감독 실행/복구 방식, 실행 전 백업 저널, 진행·실패·복원 상태 기록을 설계한다. 기존 앱의 수동 복원 버튼과 정상 취소 기능은 완료 기능으로 유지한다.
- **완료 기준:** 강제 종료·통신 단절·일부 결과 수신·복원 실패를 구분한다. 원본 복원과 12 DB 해시 확인이 끝나기 전에는 시험 성공으로 기록하지 않는다. 복원 자체가 실패하면 백업 경로와 수동 복구 절차가 남는다.
- **제약:** 같은 Gen을 다른 작업이 사용하는 동안 복구를 덮어 실행하지 않도록 소유권/동시 사용 조건을 정한다. 분석·모델 생성 같은 변경 요청을 무조건 재시도하지 않는다.
- **검증:** 격리한 시험 세션에서 오류를 주입하고 감독 프로세스의 복구를 확인한다. 실사용 원본을 보존한 뒤 진행하며, 실패 기록을 성공 기록으로 덮지 않는다.

## R04. 국가별 동일 조건 계산 대조

- **근거:** 세 국가의 기본 fixture는 이미 존재한다. [과거 재평가](archive/2026-10-19/smart-midas-steel-integrated-evaluation.md)의 KR 대조에는 잔여 기둥 차이와 Cb 민감도 검토가 남아 있다. 단면 성질 일치는 설계식 전체 일치의 증거가 아니다.
- **범위:** 코드 판본·재료/두께·요소 ID·Ly/Lz/Lb/K·Cb·B1/B2·하중 사례/포락을 고정한 비교 표를 작성한다. 먼저 열간 주골조부터 진행하고 냉간·접합은 별도 표로 관리한다.
- **KR:** 기존 `live-kr.ts --gen-check` 결과에서 남은 기둥 차이의 조건을 추적한다. 특정 지배점의 민감도 검토를 전체 포락 대조로 대체하지 않는다.
- **CN/TW:** 동일 판본/조건의 Gen 설계 기능 사용 가능 여부부터 확인한다. CN 구판 GB50017-03을 GB50017-2017 정답으로 쓰지 않는다. 대조가 불가능한 항목은 원문 수계산·검토자 확인 등 독립 근거를 정한다.
- **완료 기준:** 값·원인·적용 조건·해결/잔여 상태가 재현 가능하다. 설명되지 않은 차이를 허용오차 확대로 통과시키지 않는다. 기본 fixture를 바꿀 때 원시 입력/결과와 기대값 변경을 구분한다.

## R05. 크레인 검증·하중 조합 확대

- **이미 완료:** 전체/일부 운행 베이, 실제 불균등 좌표, 주행보·정적 차륜 위치·편심·상대 처짐, 4/8베이 계산량 제한 제거. 이를 다음 단계 신규 개발로 다시 넣지 않는다.
- **1차 범위:** 기존 횡력/제동력 입력의 비영·양방향 사례를 TW/CN/KR 전체/일부 구간에서 라이브 확인한다. 현재 6건 라이브의 횡력/제동력은 0이며 비영 검증은 오프라인이다.
- **2차 범위:** 국가별 크레인+풍/지진 동시성·계수·사용성 조합의 원문과 적용 조건을 정리한 뒤 구현한다. 지진중량의 정적 등가 반영과 모달 질량(NMAS 등)을 구분한다. 새로운 API 기능은 사용 가능한 설치본에서 확인한다.
- **완료 기준:** 사례별 힘·모멘트 평형, 적용 구간, 하중 중복 여부, 방향/동시성, 사용성 기준을 문서와 결과에서 추적한다. 한 국가의 계수/조합을 다른 국가에 그대로 적용하지 않는다.
- **별도 상세 범위:** 피로·차륜 국부지압·횡전단/비틀림·레일/브래킷·접합·복수 크레인은 검토 입력과 설계 책임 범위를 먼저 정한다. 이번 구간 확장의 완료 항목으로 묶지 않는다.

## R06. 냉간성형·횡지지·접합 상세

- **TW:** [원문 검토](reference/taiwan_cold_formed_review.md)의 판본/정오표, 약축 유효폭, 하중선-전단중심 편심, 웨브 지압·휨 조합, 클리트·순단면 상세를 순서대로 다룬다.
- **CN/KR:** 국가별 냉간 근사의 적용 범위와 원문 근거를 독립적으로 관리한다. 재료 품질·연신율, 실제 지지점·지압길이 등 계산에 필요한 입력을 먼저 정한다.
- **접합/지지:** 실제 볼트 배치·접합 강성/회전능력·다경간 내부 접합·플라이브레이스/새그로드 상세를 검토한다. 이미 있는 ‘가정/설계자 확인/없음’ 입력을 상세 자동 검증 완료로 해석하지 않는다.
- **완료 기준:** 원문 수계산·한계값·적용 범위 초과·결과 등급·최적화 제외·출력 차단이 연결된다. 구현하지 않은 항목은 예비검토/전문가 검토 표시를 유지한다.
- **별도 프로젝트:** 앵커 콘크리트 정착·독립기초·지반 상호작용은 강재/베이스판 계산의 완료와 분리한다.

## R07. 결과 회수·재해석 성능

- **근거:** 큰 모델은 해석보다 표 생성·전송·파싱의 반복 비용이 클 수 있다. v2.3.4의 분할 회수는 완료했지만 체계적 성능 기준은 아직 없다.
- **범위:** 국가별 소/중/대 모델에서 해석·표 생성/회수·파싱·검토·출력 시간을 분리하고, 요청 행 수·응답 크기·최대 메모리·취소 반응을 측정한다.
- **완료 기준:** 고정 입력·설치 환경·측정 방법의 전후 결과가 있고, 개선 후에도 전체 사례와 누락/중복 검증을 유지한다. 현재 CN 최대 4조합 제한은 근거를 확인한 뒤 조정한다.
- **후속 후보:** 필요한 결과 성분 축소, 캐시/재개, 요청 분할 최적화. 로컬 선형 조합은 Gen 조합/포락과 동일성 검증 및 B1/B2 적용 순서 검토 전에는 도입하지 않는다.

## R08. 산출물·출처·시험 증거 보존

- **이미 완료:** HTML/PDF·DXF·CSV 직접 출력과 기본 글꼴 검증. 이를 새 출력 기능으로 다시 등록하지 않는다.
- **범위:** R01의 프로젝트/개정과 입력·해석·검토·산출물을 연결한다. 앱·Gen/DB 버전·규범 판본·단면 출처·확인 가정·제외 물량을 추적한다. 로컬 `output/`에만 있는 검증 근거의 전달/보존 방식을 정한다.
- **단면 출처:** 미해결 8개는 제외 유지한다. 설치 DB 변경, 런타임 주요 성질 대조와 배포 시 Z/Cw·파일 해시 검증 범위를 구분하고 재발행 절차를 문서화한다.
- **완료 기준:** API 키 없이 입력·검증 요약·파일 목록/해시·실패/재시험/복원 상태를 전달할 수 있다. 예전 계산서를 최신 개정 출력으로 표시하지 않는다.
- **견적 경계:** 접합 판재·볼트·용접/도장 추정량과 미산정 클립·플라이브레이스·레일 상세·로스/발주량을 구분한다. 현재 물량표를 제작/발주 상세로 과장하지 않는다.

## R09. 실제 사용자 업무·접근성 검증

- **범위:** 4개 언어 × 대표 국가/템플릿에서 첫 방문 → 입력 오류 수정 → 추가 구조 → 생성 → 검토 → 보완 → 산출물의 작업 시험을 정한다. 좁은 화면, 키보드, 포커스 이동·숨김 콘텐츠, 긴 작업 실패/취소도 확인한다.
- **완료 기준:** 처음 쓰는 사람이 오류 원인과 다음 행동을 알아보고 작업을 끝낼 수 있다. 크레인 설정 때문에 건물 형상을 다시 만들도록 유도하지 않는다. 상태 문구의 국가/언어 혼동과 ‘입력 확인=설계 합격’ 오해가 없다.
- **근거:** 기존 7단계·클릭형 업무·모달 개선은 완료됐다. 새로운 대화창/중복 단계/추가 장식을 도입하는 작업으로 되돌리지 않는다.

## R10. 배포·설치 지원 정책

- **범위:** 웹 배포(steel.midasapi.space) 운영 방식, 지원하는 Gen NX 설치본·단면 DB·규범 판본, 로컬 MAPI 연결 요구사항과 설치 안내를 정한다.
- **완료 기준:** 지원/미지원 판본이 문서와 화면에 명시되고, 판본이 다를 때의 동작(차단 또는 경고)이 정해진다.
- **근거:** 초기 README 미정 항목 `배포/설치 방식`. Vercel 자동 배포는 이미 운영 중이며, 이 항목은 지원 정책의 확정을 뜻한다.

## R11. GB 51022 7장 门式刚架 부재 설계

- **현재:** CN 하중·변위·세장비·η·γRE·내진 상세·隅撑은 GB 51022-2015를 따르지만, 부재 강도·안정은 GB 50017-2017 식으로 대신 계산한다. Gen 과 무관한 앱 구현 범위다(CN 은 Gen 설계 API 를 쓰지 않음).
- **범위:** 1단계 7.1.1 웨브 좌굴후강도(유효폭 ρ·kσ, 전단 φps)와 7.1.2 강도·전단 상호작용·가새/스티프너. 2단계 7.1.3~7.1.5 변단면(楔形) 기둥·보 안정과 부록 A 계산길이 — 용접 변단면 H 단면 모델링(Gen 단면·물량·도면 포함)과 함께.
- **완료 기준:** 원문 KB(`COde/CN/knowledge/gb51022-2015/07-构件设计`) 조항별 손계산 대조 회귀, 압연 등단면 기본 모델에서 GB 50017 결과와 차이·지배식 비교 기록, 계산서 근거 표시 갱신.
- **근거:** 실제 중국 경량 门式刚架는 얇은 웨브의 용접 변단면 H 가 일반적이며, 이 경우 GB 51022 7장이 지배한다. 현재 압연 H 기본 단면에서는 웨브가 두꺼워 차이가 작고 GB 50017 쪽이 대체로 보수적이다.

## 갱신 규칙

작업 시작 시 고정 ID에 착수 범위·담당·기준 커밋을 적고, 완료 시 구현 커밋·시험 조건·잔여 한계를 연결한다. 새 기능에 완료 체크를 넣을 때 API 연동 성공과 구조 계산 검증을 구분한다. 사용자 선호에 따라 일반 개선은 패치로 묶고, 마이너 버전 변경은 먼저 상의한다.
